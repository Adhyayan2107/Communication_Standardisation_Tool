# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Consuma's own team — marketing/comms and recruiting people who draft and publish external content (LinkedIn posts, outbound emails, job descriptions, website copy) and need it to comply with the Brand Constitution before it ships. Built as a real internal tool; the Founder's Office take-home assignment is the occasion for building it, not its intended audience.

## Product Purpose

A two-stage content-governance web app. Stage 1 generates on-brand content strictly from a machine-readable Brand Constitution (`constitution/brand_constitution.json`). Stage 2 validates every draft with a deterministic check registry written in code. It exists because Consuma's public communications had drifted — conflicting claims, banned lexicon, inconsistent CTAs — as documented in the "Consuma Public Communication Audit" that produced the constitution file. Success is every shipped piece reaching "ON STANDARD" (zero FAIL rows on the ledger), with the result provably derived from the constitution file rather than from loose prompting.

## Positioning

The model executes the standard; it never defines it. Nearly every check is deterministic TypeScript (regex/string logic), not model judgment — only two rules (max-one-metaphor, per-channel structure) are ever model-judged, and even those return strict, parseable JSON with no free text. A neighboring "AI content generator" could not truthfully copy this: the differentiator is precision of standard-modeling, not prompting quality.

## Operating Context

Channels: LinkedIn posts, outbound emails, job descriptions, website copy. Two first-class workflows:

1. **Generate** — brief in → draft generated from the compiled constitution prompt → deterministic lint (+ the 2 model-judged checks) → auto-fix rewrites only flagged spans → re-lint → ship once the ledger shows zero FAILs.
2. **Audit** — existing or legacy copy is pasted into the draft editor (contentEditable, re-lints on blur) and checked/fixed against the same standard, independent of whether it was generated by the tool.

`constitution/brand_constitution.json` is the single source of truth; the prompt compiler, the check registry, and the UI all read from it — nothing is hardcoded elsewhere. Deployed as a single Next.js repo on Vercel with no database; run history persists client-side in `localStorage` (capped at 50 entries) since API routes must stay stateless.

## Capabilities and Constraints

- All generated and audited content is strictly derived from the constitution file — no rule, claim, banned word, or CTA string is hardcoded anywhere else.
- Deterministic checks cite a rule ID and the offending span for every failure. Only VX-2 (max one metaphor) and the per-channel structure rule are model-judged, via a strict-JSON audit endpoint.
- Auto-fix rewrites only flagged spans, then re-lints — it does not rewrite compliant text.
- The model must never invent statistics, findings, or client names (registry rule CL-6).
- The check registry is designed for extension: adding a future check means appending one object to the `CHECKS` array — no UI or route edits.
- The compiled system prompt is viewable in the UI as demo evidence that it's derived from the constitution, not authored separately.
- Constitution content itself is a human decision: if two rules conflict, the tool stops and asks rather than silently editing the standard.

## Brand Commitments

- Company name in body copy is always "Consuma." "Consuma AI" is permitted only as a first-mention press disambiguator; "Consuma.ai" is a URL, never a name in prose.
- Product name is "Rapid Research Platform" on first mention, "the platform" thereafter; "RRP" only after expansion in the same piece. Never "AI Engine."
- The one-line descriptor is used verbatim (no paraphrase) in bios, boilerplate, email signatures, and JD intros: "Consuma is an AI-powered rapid research platform that turns a research brief into a decision-ready consumer insights report in under 30 minutes."
- Voice reference: the founder's press voice, systematized — sharp, specific, contrarian, metaphor-led but disciplined (maximum one metaphor per piece).
- Exactly two CTAs exist across all channels: "Book a demo" (primary) and "Download the report" (secondary). No other CTA string is permitted.
- Full ruleset lives in `constitution/brand_constitution.json` v1.0 (2026-07-24), sourced from the "Consuma Public Communication Audit (Adhyayan Gupta, Jul 2026)."

## Evidence on Hand

- `constitution/brand_constitution.json` — the full v1.0 ruleset; the single source of truth for identity, claims, voice, CTA, and channel rules.
- `reference/consuma_standard_tool.jsx` — a working single-file prototype (claude.ai artifact) with correct `compileSystemPrompt`, lint, inline-violation-highlighting, and auto-fix logic to port faithfully, not reinvent.
- The claims registry documents real conflicting variants found live in Consuma's own communications during the audit (e.g. speed claimed variously as "within seconds," "just minutes," and "5–15 minutes," now superseded by the single canonical "under 30 minutes").
- A "gold mine" legacy LinkedIn post (in the reference JSX) is the canned demo failure case — it must trip VX-3, VX-4, VX-5, VX-6, and CH-CTA as FAILs, plus a CH-LI length/structure WARN.
- No user testimonials, pricing, or live deployment metrics exist yet; future work must not fabricate any.

## Product Principles

1. The model executes the standard; it never defines it — every generation and every check traces back to the constitution file, never to prompt-writer discretion.
2. Objective checks are deterministic; subjective judgment is minimal and constrained — only 2 rules are ever model-judged, and both return strict, parseable JSON.
3. Extensibility is a first-class design goal — a new check must cost one registry entry, never a UI or route change.
4. Rule changes are a human decision — conflicts or ambiguity in the standard stop the tool and prompt a human, rather than being silently resolved.
5. Drafting and auditing are equally real workflows — the tool must serve people writing new content and people checking content that already exists.

## Accessibility & Inclusion

Usable down to 360px width; visible keyboard focus rings; semantic headings; the compliance ledger renders as a real `<table>`. No further user-specific accessibility requirement has been established.
